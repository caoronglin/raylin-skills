# 每日自我进化复盘

> 目标：让今天的经验变成明天的规则，而不是明天的重复。

---

## 五段式结构（固定顺序，缺段要说明原因）

### ① 回顾完成

列出当日**真实完成**的任务（不是计划、不是"进行中"）。

🛑 **只写 JOURNAL 里有记录的事**。如果某任务只在别处被转述、JOURNAL 无完成记录 → 标记为**日志缺口**，并**当场补写**，不要让它继续漂着。
（2026-08-08 实测：BSA-seq 综述 / NWAFU 爬虫仅在复盘里被转述，JOURNAL 无记录 → 确认日志缺口。）

### ② 新观察

当日出现的**规律性现象**，而非事件复述。写"趋势/模式"，不写"我做了 X"。

### ③ 进化策略

把观察转成**可执行规则**。每条必须能回答：下次遇到同样情况，具体做什么不同？

### ④ 认知偏差修正

当日被证伪的假设、被纠正的判断。格式：`原以为 → 实际是 → 影响`。

### ⑤ 挂起项闭环

见下方协议。

---

## 🔴 三条硬规则

### S1 · 复盘去重规则

```
if 当日无新 JOURNAL 记录:
    → 只做【挂起项实测核查】+【策略审计】
    → 禁止复读上一条复盘的结论
    → 输出需明确标注"当日无新日志"
```

**动因**：2026-08-07 与 08-06 复盘高度重复，复盘沦为复读机 → 该规则由此产生。

### S2 · 挂起项闭环协议

每个挂起项**每次必须实测**，输出三态之一：

| 状态 | 含义 | 动作 |
|---|---|---|
| `已闭环` | 实测确认解决 | 关闭并记录证据 |
| `仍存在（第 N 天）` | 实测仍在 | 记天数 |
| `已变化` | 状态改变但未解决 | 更新描述 |

🛑 **超过 7 天未闭环 → 自动降级为"主动修复"任务**，不再继续观察。

> 实测样例：IPv6 回环 `ping -6 ::1` 自 8/2 起 General failure，第 9 天仍未自愈 → 8/8 执行 `netsh ipv6 reset`（提示需重启完成）→ 升级为待重启验证。

**三态必须是实测结果**，禁止凭印象填"应该好了"。

### S3 · 任务完成即写 JOURNAL

任务完成的**当时**就写，不要攒到复盘。复盘只做提炼，不做补录。

## 复盘触发器（满足任一即做）

- 单任务工具调用 ≥ 5 次，或经历多轮修正
- 用户明确纠正、否定、补充偏好
- 工具调用失败并发现了 workaround 或正确用法
- 完成文件型交付物（报告、PPT、脚本、表格、整理目录）
- 发现提示词 / 记忆 / 技能说明过时或互相冲突

---

## 沉淀去向（各归其位，禁止串味）

| 内容性质 | 写到哪 | 工具 |
|---|---|---|
| 一次性事件、完成记录、临时复盘 | `memory/JOURNAL.jsonl` | `mcp__agent-memory__memory` → `append` |
| 6 个月后仍有价值的事实、规则、技术决策 | `memory/FACT.md` | `mcp__agent-memory__memory` → `update` |
| 改变**行为方式**的身份/风格/原则/边界 | `SOUL.md` | Read + Edit |
| 用户身份、偏好、环境、长期上下文 | `USER.md` | Read + Edit |

🛑 **禁止记录**：未发表敏感序列、私密实验设计、凭证、密钥、个人隐私。

**复盘格式**：`做了什么 → 哪点可复用 → 是否需要沉淀为规则`

## 输出模板

```markdown
## YYYY-MM-DD 每日自我进化复盘

### ① 完成
- {任务}（证据：JOURNAL {日期}）
- 日志缺口：{若有} → 已补写

### ② 新观察
- {规律性现象}

### ③ 进化策略
- S{n}：{可执行规则}

### ④ 认知偏差修正
- 原以为 {} → 实际 {} → 影响 {}

### ⑤ 挂起项
- {项}：已闭环 / 仍存在（第 N 天）/ 已变化 → {动作}
```

## 反例黑名单

1. ❌ 当日无新日志仍长篇复读昨日结论 → 触发 S1
2. ❌ 挂起项不实测、凭印象写状态 → 违反 S2
3. ❌ 把"计划做"写成"已完成"
4. ❌ 复盘只描述事件、不给可执行规则（等于没复盘）
5. ❌ 把一次性事件写进 FACT.md，或把长期规则只写 JOURNAL
6. ❌ 策略写了但下条复盘不检查是否被执行 → 策略审计缺失
